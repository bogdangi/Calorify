📝 User Story: Test Coverage

Title: Testing Strategy
Feature: Unit tests for business logic, IndexedDB repositories, import validation, i18n, and the ML pipeline with mocks
User Story:
• As a maintainer,
• I want automated tests covering core business logic and the mock-first pipeline,
• So that refactoring (e.g. swapping the real model in) cannot silently break the app.

Status: ✅ Mostly done — 6 test files, 28 tests passing (`npm test` green); gaps remain around component-level tests and edge cases. `npm run build` verified passing too.

⚙️ Acceptance Criteria

1. Covered functions: calculateDailyCalories, calculateWeeklyCalories, calculateMonthlyCalories, weight change, calories-from-portion. (Note: §22 names `calculateAverageCalories`, which exists embedded inside the daily/weekly statistics rather than as a standalone export.)
2. Covered scenarios: no meals, one meal, multiple meals, meal editing, meal deletion, weight changes, missing data, timezone/date handling, IndexedDB repositories (fake-indexeddb), import validation, i18n switching.
3. ML: real models are NEVER run in unit tests; pipeline is tested end-to-end with MockFoodClassifier/MockFoodDetector/MockPortionEstimator.
4. `npm ci` and `npm run build` remain part of the verified workflow.
